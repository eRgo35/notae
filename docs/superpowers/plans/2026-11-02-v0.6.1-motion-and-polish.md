# Notae 0.6.1 Motion and Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Compose app the motion a current Android app has (screen transitions, animated dialogs and sheets, state fades, list item motion, haptics) and fix the screens that look wrong in 0.6.0.

**Architecture:** One shared set of motion specs built on the 0.3.0 tokens (120 / 220 ms, 24 dp shift). Navigation 3 gets explicit push, pop, predictive-pop and lateral (section switch) transitions. Overlays keep their last content while they animate out, through one wrapper that `ModalSurface` reads. Everything else is local `animate*AsState`, `AnimatedVisibility`, `Crossfade` and `Modifier.animateItem()`.

**Tech Stack:** Kotlin 2.4, Jetpack Compose (BOM 2026.06.01), Navigation 3 1.1.7, navigationevent 1.1, Robolectric + Roborazzi.

**Spec:** the audit and plan approved in the 2026-11-02 session (all steps; tablet portrait details stack vertically; haptics on).

## Global Constraints

- No new dependencies (the launch window colours use platform theme attributes, `values-v31` for the splash).
- Durations come from `Tokens.motionShortMillis` (120), `Tokens.motionMediumMillis` (220) and `Tokens.motionShift` (24 dp).
- Animations follow the system animator scale; Compose applies it. The banner's sweep keeps its `animationsEnabled` check.
- Production code avoids unchecked `unwrap`/`expect` (Rust) and `!!` (Kotlin).
- Conventional Commits, one commit per task.
- After a visual change, re-record Roborazzi baselines and review them.

## Review Focus

- A tap on a dialog or sheet while it animates out must not dispatch a second action (Dismiss twice, Save twice). Task 3 test.
- A reorder drop must not snap the row back to its old slot before the new order arrives. Task 6 test.
- TalkBack must not find a closed dialog during its exit animation. Task 3 test.
- A section switch must not play the push slide (it is not deeper navigation). Task 2 rule `isLateral`.
- The large phone title must never rest half folded after a fling or a drag ends. Task 7 test.

### Task 2: Screen transitions

**Files:** Modify `nav/NotaeNavDisplay.kt`.

- [ ] `internal fun isLateral(initial: Scene<*>, target: Scene<*>): Boolean`: true when the root entry's content key (first of `previousEntries + entries`) differs. A section switch, Setup → Library and Loading → anything are lateral.
- [ ] Pass `transitionSpec`, `popTransitionSpec` and `predictivePopTransitionSpec` to `NavDisplay`:
  - lateral: fade-through (fade out 90 ms, fade in 220 ms after 90 ms delay).
  - push: new screen slides in from the end by `motionShift` and fades in; old one fades out, 220 ms.
  - pop: the reverse.
  - predictive pop: the outgoing screen scales to 0.9 and fades.
- [ ] `ListDetailScene`: the list width animates (`animateDpAsState`, medium). The detail pane enters with slide-in from the end plus fade.
- [ ] Test (`ListDetailSceneTest`): `isLateral` true for Library(all) → Library(recent), false for Library(sets) → Set.
- [ ] Commit `feat(android): animate screen changes`.

### Task 3: Dialog and sheet motion

**Files:** Create `ui/components/Overlay.kt`; Modify `ui/components/NotaeDialog.kt`, `ui/components/ActionSheet.kt`, every overlay call site (`NotaeNavDisplay`, `SetOverlays`, `LibraryScreen` sheets, `PhoneChrome` composer sheet, `AddToSet`, `NoteItems`, `SettingsScreen`); Test `ui/components/OverlayTest.kt`.

- [ ] `@Composable fun <T : Any> AnimatedOverlay(value: T?, content: @Composable (T) -> Unit)`: keeps the last non-null value while exiting. It provides an `AnimatedVisibilityScope` through `LocalOverlayScope`. While exiting, the content gets `clearAndSetSemantics {}` and swallows pointer input.
- [ ] `ModalSurface` reads `LocalOverlayScope`:
  - scrim: `animateEnterExit` fade.
  - dialog card: fade plus scale from 0.92.
  - sheet: slide up from the bottom, medium in, short out.
  - with no scope (screenshot tests), it renders as now.
- [ ] Sheets: `draggable` vertically on the card. A release past 30% of its height, or with fling velocity over 1000 dp/s, calls `onDismiss`; otherwise it springs back.
- [ ] Back progress: `LocalBackProgress: () -> Float` (0 when idle), fed from the `NavigationEventState.transitionState` of the back handlers in `NotaeNavDisplay` and `LibraryScreen`. `ModalSurface` scales the card down to 0.95 and, for a sheet, moves it down by up to 10% of its height.
- [ ] Tests:
  - `dismissedDialogLeavesSemanticsAtOnce`: after the value goes null, `onNodeWithText` finds nothing while the clock is paused mid-exit.
  - `clickDuringExitDoesNothing`.
  - `sheetDraggedDownDismisses`: `swipeDown` on the card calls `onDismiss`.
  - `shortDragSpringsBack`.
- [ ] Commit `feat(android): animate dialogs and sheets, drag sheets to close`.
