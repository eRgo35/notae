# Notae v0.2.1 plan

Sections are appended per issue. Each records the reproduction, the root cause and what was and was not verified; the Galaxy Tab S10 FE+ stays untested unless a section says otherwise.

## Scan progress bar (#30)

**Reproduced** on the API 35 emulator (`emulator-5554`, v0.2.0 baseline, fixture library `/sdcard/Download/NotaeOps`): the moment a scan reached "Reading PDF text and thumbnails: 0 of 4" the bar showed a blue fill of about 30 % (`target/emulator-evidence/v021-motion/base-scan-strip.png`, 8th–9th tiles).

**Root cause.** The projection was honest (`OperationBanner::fraction` was `0.0` until counts existed). `OperationBanner` in `ui/library.slint` rendered `parent.width * (fraction > 0 ? fraction : 0.3)`: a hard-coded 30 % placeholder fill for "indeterminate", which a reader takes as progress. `0.0` was also overloaded: an unknown total and a known `0 of N` were indistinguishable.

**Fix.** `OperationBanner::fraction` is `Option<f32>` (`None` = no real total, `Some(0.0)` = known `0 of N`). The Slint property uses a negative value for unknown. The bar's determinate fill is exactly `fraction` of the track (zero when unknown); an unknown total draws an empty track plus a moving 30 % segment that exists only while Android animations are on, so it cannot be read as a value. `update_rescan_progress` ignores a stale event that would move the count backwards. Tests: `operation_banner_ui` (red first: fill width 272.4 px of a 908 px track at unknown total), `operation_state::reading_progress_never_moves_backwards` and the existing phase tests.

## Settings maintenance card (#29)

The Library maintenance Scan button is removed (supersedes #11/#12); the Library header Scan is the only Scan action. The maintenance card keeps only its title and fact rows, so it has the density of the Library folder and About cards (16 px padding, 8 px row spacing). Scan outcomes stay visible through the status banner and the Last scan / ID conflicts / Failures rows.

The "enormous card" could not be reproduced on the emulator at wide or compact sizes in either theme; the only source of excess height found is the 48 px Scan icon button inflating the heading row (about 24 px taller than the text), now gone. `maintenance_card_keeps_the_density_of_the_other_settings_cards` asserts the card never exceeds padding + title + its rows + spacing at 360×800 and 1280×800 (a stretched card fails it). Theme colour does not affect geometry, so the host test does not loop over themes; light and dark emulator captures are in `target/emulator-evidence/v021-motion/`.
