# Notae 0.7.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone v0.7.0: sliding screen motion (#49), set artwork as a stack of score previews (#50), score notes and set notes (#47), and sharing a set (#51).

**Architecture:** Motion stays in `ScreenMotion` (`nav/NotaeNavDisplay.kt`), which now learns the section order from the snapshot. Notes are Rust core state: a new `score-notes.json` store keyed by content key, and an optional `set_note` on set items (sets file v2). Sharing reuses the export format with a `"kind": "set"` marker. The core builds the file and its text list and hands them to Kotlin as an effect. Kotlin only writes the file to the cache, sends it through a `FileProvider` URI, and feeds received files into the existing `import_file_read` path.

**Tech Stack:** Rust 1.98.1 core with UniFFI, serde_json; Kotlin 2.4, Jetpack Compose (BOM 2026.06.01), Navigation 3 1.1.7, Robolectric + Roborazzi.

**Spec:** issues #49, #50, #47 and #51, ADR `docs/adr/0003-in-app-viewer-and-overlays.md`, `GLOSSARY.md`, plus the decisions settled in the 2026-11-11 session, copied here:

| # | Decision |
|---|----------|
| D1 | Deeper screens (Set, Details, Search, Settings) slide in **full width**, 300 ms, `NotaeMotion.emphasized`, **no fade**. The screen underneath stays still. |
| D2 | Section switches slide **full width**, both sections moving together, 300 ms, in rail order: `snapshot.sections` keys, then `snapshot.composers` keys. |
| D3 | Setup → library and Loading → first screen **keep today's fade-through**. |
| D4 | Score notes live in `score-notes.json` as `{key, path, text}`, relinked by path like favorites. |
| D5 | The sets file goes to schema v2 with an optional `set_note` on piece items. v1 still loads. Downgrading is not supported. |
| D6 | Notes show in **Details**: the score note always, and the set note (labelled with the set's name) when Details was opened from a set row. Set rows with a set note show a marker. |
| D7 | Notes are edited in the existing `NoteEditor` dialog. Blank text clears the note. |
| D8 | Export v2 adds `score_notes`; v1 files still import. A shared set uses the same format with `"kind": "set"`, exactly one set, no favorites and no score notes. |
| D9 | Shared pieces carry `number`, `title` and `composer`, used **once at import** to match by key → path → number + title. Unmatched pieces keep the sender's key and path and show as today's missing placeholder. |
| D10 | Share is a toolbar icon in the open set **and** an entry in the set's ⋮ sheet. Both open a menu: **Share set** / **Share set with notes**. The choice opens the Android share sheet with one `ACTION_SEND` carrying the file (`EXTRA_STREAM`) and a readable list (`EXTRA_TEXT`). |
| D11 | Importing a shared set whose id exists offers **Replace** or **Keep both**. Keep both takes a new id and the name `"<name> (2)"`, or `(3)` and so on if that name is taken. |
| D12 | A shared file received before a library is open waits. Its review shows once the library screen is up. |
| D13 | MIME type `application/json`. Notae accepts `application/json` and `application/octet-stream` from Open with and Share to, then checks the contents. |

## Global Constraints

- No new dependencies. `androidx.core.content.FileProvider` already comes with AppCompat.
- Production code avoids unchecked `unwrap`/`expect` (Rust) and `!!` (Kotlin). `unsafe` stays forbidden.
- No network access. Sharing goes only through Android's share sheet.
- Motion durations come from tokens. Add `Tokens.motionLongMillis = 300`. Nothing exceeds 500 ms (One UI's limit). The system animator scale is respected because Compose applies it; don't override it.
- English and Polish strings for every new label (`res/values/strings.xml`, `res/values-pl/strings.xml`).
- Use the glossary terms: score note, set note, set description, text note. "Annotation" is never used.
- Conventional Commits, one commit per task. Run `scripts/check.sh` (fast) before every commit. Run `scripts/check.sh full` before the release task.
- After a visual change, run `apps/notae-android/gradlew -p apps/notae-android recordRoborazziDebug` and review every changed image.

## Review Focus

1. **A set holding the same score twice:** each occurrence keeps its own set note, and editing one never changes the other. Pinned in Task 5 (`set_note_is_per_occurrence`).
2. **A shared file that is a full backup, or a backup opened through Open with:** it must go to the existing backup confirmation, never to the shared-set review, and vice versa. Pinned in Task 9 (`parse_export_tells_backup_from_shared_set`).
3. **Keep both while "Name (2)" already exists:** the copy is named "Name (3)" and gets a new id. Item ids stay unique within the set. Pinned in Task 10.
4. **A rescan after a PDF edit (new content key, same path):** the score note follows by path and isn't lost or duplicated. Pinned in Task 4 (`score_note_relinks_by_path`).
5. **Section switch to a composer chip, or to a key missing from the order:** it must still slide (unknown keys count as the end of the order) and must never play the push slide. Pinned in Task 1 (`unknownSectionSlidesFromTheEnd`).
