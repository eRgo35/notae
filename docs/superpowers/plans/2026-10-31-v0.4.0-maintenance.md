# v0.4.0 Maintenance Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Notae cheap to develop and release as a private, solo-maintained repo: quality gates and releases run on the maintainer's PC, GitHub Actions runs only a light check, and the docs (README, ROADMAP, CONTRIBUTING) describe the project and its workflow as it is now.

**Architecture:** Three shell scripts in a new top-level `scripts/` directory carry the workflow: `check.sh` (local gates, `fast` and `full`), `hooks/pre-push` (opt-in, runs `check.sh fast`) and `release.sh` (build, sign, verify and publish a tagged release from this PC). The three existing scripts in `.github/scripts/` move to `scripts/` because nothing in GitHub Actions uses them any more. `ci.yml` shrinks to one job (fmt, clippy, tests); `release.yml` is deleted. No app code changes.

**Tech Stack:** Bash (checked with `shellcheck`), GitHub Actions (first-party actions only), `gh` CLI, cargo-apk2 1.4.0, Android build-tools `apksigner`/`aapt2`.

**Spec:** No separate spec. The decisions below were made by the maintainer on 2026-10-30/31 and are authoritative.

## Decisions (maintainer, 2026-10-30/31)

- GitHub Actions minutes ran out on the private repo; v0.3.0 was released from the maintainer's PC.
- Local gates: one script with `fast` and `full` modes, plus an **opt-in** pre-push hook. No mandatory hook (AGENTS.md).
- GitHub CI: a light check on pull requests and `main` (fmt, clippy, tests), cached; the weekly dependency audit stays. Releases are built locally.
- The repository stays **private**. Docs are written for the maintainer and Claude, not outside contributors.
- 0.4.0 is maintenance only. 0.5.0 is the Compose migration (`docs/superpowers/plans/2026-10-30-compose-migration.md` on `feat/compose-migration`).

## Decisions this plan makes (confirm before executing)

1. Move `.github/scripts/*` to `scripts/` (they become local tools).
2. Delete `release.yml` instead of keeping it as a manual fallback (it needs the signing secrets and ~70 CI minutes per release).
3. Drop the Android arm64 compile job from CI; it runs in `check.sh full` and in every release.
4. Coverage, `cargo deny check`, rustdoc and the CLI smoke run only in `check.sh full`, not in CI.
5. Dependabot checks monthly instead of weekly (each update PR costs a CI run).
6. CI skips pushes and PRs that change only Markdown or `docs/`.
7. Delete `docs/superpowers/IMPLEMENTATION-STATE.md` (frozen at 2026-10-18); `ROADMAP.md` and the milestones replace it.
8. Add the root `GLOSSARY.md` that `AGENTS.md` and `docs/agents/domain.md` already point to.

## Global Constraints

- Rust 1.98.1 from `rust-toolchain.toml`; the gate commands are exactly those in `docs/engineering-standards.md` today.
- Coverage floor stays `--fail-under-lines 84`.
- Android toolchain: NDK r26d (`$ANDROID_HOME/ndk/android-ndk-r26d` locally, `26.3.11579264` in CI), cargo-apk2 1.4.0, JDK sources compiled as Java 17.
- Release certificate SHA-256 (public, pinned): `BE:27:CD:78:17:66:C5:C2:8A:9D:B1:06:C0:7B:05:1C:EE:E4:E0:00:31:05:96:45:95:E2:A8:48:F3:71:F6:01`.
- Release keystore: single-entry PKCS12 at `~/.android-keys/notae-release.p12`, alias `notae-release`. Never committed, never echoed, password read with `read -rs`.
- Release tags point at commits on `origin/main`; tag `vX.Y.Z` equals the `[workspace.package] version`.
- Scripts: `#!/usr/bin/env bash`, `set -euo pipefail`, clean under `shellcheck`, run from any directory (they `cd` to the repo root).
- No new dependencies and no third-party GitHub Actions. Only `actions/*`.
- Conventional Commits; reference the v0.4.0 issue for each task in the commit body.

## Review Focus

1. A script started from a subdirectory or from another worktree must act on the repository the script lives in, not the caller's cwd. Test in Task 1.
2. A missing tool (cargo-deny, cargo-llvm-cov, cargo-apk2, the NDK) must stop `check.sh full` **before** any gate runs, naming the install command. Test in Task 1.
3. `release.sh` must refuse to publish when the tag is missing, not pushed, not on `origin/main`, does not match the Cargo version, or already has a GitHub Release, and must never upload when the signature check fails. Tests in Task 2.
4. An interrupted or failed `release.sh` (Ctrl-C, wrong password) must leave no temporary worktree and no partial GitHub Release. Test in Task 2.
5. A docs-only change must not spend CI minutes, while any change to code, `Cargo.lock` or a workflow still runs CI. Checked in Task 3.

### Task 1: Local quality gates (`scripts/check.sh` and the opt-in hook)

**Files:**
- Move: `.github/scripts/build-apk.sh`, `prepare-release-keystore.sh`, `verify-release-apk.sh` → `scripts/` (`git mv`; fix the `repo=` line in `build-apk.sh`, which climbs two levels today and must climb one)
- Create: `scripts/check.sh`, `scripts/hooks/pre-push`

**Interfaces:**
- Produces: `scripts/check.sh [fast|full]` (default `fast`), exit 0 only when every gate passes. Later tasks call `scripts/check.sh full` and `scripts/build-apk.sh release`.

Behaviour of `check.sh`:
- `cd "$(git -C "$(dirname "$0")" rev-parse --show-toplevel)"`.
- `fast`: `cargo fmt --check`, both clippy commands, `cargo test --workspace`.
- `full`: `fast`, then `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps`, `cargo deny check`, `cargo llvm-cov --workspace --summary-only --fail-under-lines 84`, `cargo run -p notae-index-cli -- --help`, `cargo apk2 check -p notae-android --target aarch64-linux-android`. `cargo llvm-cov` reuses its own `target/llvm-cov-target`; do **not** `cargo clean` locally.
- `full` checks prerequisites first: `cargo-deny`, `cargo-llvm-cov`, `cargo-apk2` on `PATH` and the NDK directory. On a miss it prints `missing: <tool> (install: cargo install --locked --version <v> <tool>)` or `missing: NDK at <path> (set ANDROID_NDK_ROOT)` and exits 1 before any gate. It uses the same `ANDROID_HOME`/`ANDROID_NDK_ROOT`/Java 17 defaults as `build-apk.sh` (copy those few lines; don't add a shared file).
- Prints `==> <gate>` before and the elapsed seconds after each gate, stops at the first failure, ends with `All <n> gates passed in <s>s`.

`hooks/pre-push`: `exec "$(git rev-parse --show-toplevel)/scripts/check.sh" fast`. Installed per clone with `git config core.hooksPath scripts/hooks`; skipped once with `git push --no-verify`.

- [ ] **Step 5: Fails on a violation.** Add two consecutive blank lines inside a function in `crates/notae-domain/src/lib.rs`, run `scripts/check.sh fast`. Expected: exit 1 after `==> cargo fmt --check`, no clippy line. Revert.

### Task 2: Local release (`scripts/release.sh`) and removal of `release.yml`

**Files:**
- Create: `scripts/release.sh`
- Delete: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `scripts/check.sh full`, `scripts/build-apk.sh release`, `scripts/verify-release-apk.sh APK TAG DIST_DIR BUILD_TOOLS_DIR` (Task 1).
- Produces: `scripts/release.sh vX.Y.Z`. Run by the maintainer in their own terminal (it prompts for the keystore password).

Behaviour, in this order, each failure exiting 1 with a one-line reason:
1. Preflight: tag matches `v[0-9]+.[0-9]+.[0-9]+`; `docs/release-notes/<tag>.md` exists; tag equals `v` + the `notae-android` version from `cargo metadata`; the tag exists locally and `git ls-remote --tags origin <tag>` finds it; after `git fetch origin main`, the tag commit is an ancestor of `origin/main`; `gh release view <tag>` fails (no release yet).
2. `git worktree add --detach "$tmp/src" <tag>`, with `trap` removing the worktree (`git worktree remove --force`) and `$tmp` on `EXIT` and `INT`.
3. `scripts/check.sh full` inside the worktree.
4. Keystore `${NOTAE_RELEASE_KEYSTORE:-$HOME/.android-keys/notae-release.p12}`; `read -rsp` the password; run `scripts/build-apk.sh release` in the worktree with `CARGO_APK_RELEASE_KEYSTORE`/`_PASSWORD` set for that command only.
5. `NOTAE_RELEASE_CERT_SHA256=<pinned value> scripts/verify-release-apk.sh <apk> <tag> "$tmp/dist" <newest $ANDROID_HOME/build-tools/* by sort -V>`.
6. `gh release create <tag> --verify-tag --title "Notae <tag>" --notes-file docs/release-notes/<tag>.md --generate-notes "$tmp/dist"/notae-<ver>-arm64.apk{,.sha256}`, then print the release URL.

Gates and the build run in the worktree, so the published APK always comes from the tag, whatever the main checkout contains.

- [ ] **Step 1:** Write `release.sh`, `chmod +x`, `shellcheck scripts/release.sh`. Expected: no output.
- [ ] **Step 2: Version mismatch.** `scripts/release.sh v9.9.9` (create an empty `docs/release-notes/v9.9.9.md` first, delete it after). Expected: exit 1, `tag v9.9.9 does not match the Cargo version 0.3.0`.
- [ ] **Step 3: Existing release.** `scripts/release.sh v0.3.0`. Expected: exit 1, `GitHub Release v0.3.0 already exists`, and no worktree in `git worktree list`.
- [ ] **Step 4: Unpushed tag.** `git tag v0.3.0-local-test && scripts/release.sh v0.3.0-local-test`. Expected: exit 1 at the tag-format check. Delete the tag. (A real unpushed release tag is exercised by Task 6.)
- [ ] **Step 5: Interrupt cleanup.** Temporarily make preflight pass for `v0.3.0` (comment out the existing-release check locally, do not commit), run it, press Ctrl-C during `check.sh full`. Expected: `git worktree list` shows no temp worktree. Restore the check.

"Development workflow" in CONTRIBUTING.md is the solo-maintainer pipeline, one short step each:
1. Issue with a triage label and a milestone.
2. Branch (`feat/…`, `fix/…`) or worktree under `.worktrees/`; multi-step work gets a plan in `docs/superpowers/plans/`; UI or architecture ideas can be mocked as a private Claude Artifact before code.
3. Test-first; `scripts/check.sh fast` while working (or the opt-in hook on push).
4. PR to `main`; the light CI runs; `scripts/check.sh full` locally before merge, stated in the PR.
5. Device check with `scripts/build-apk.sh dev` on the emulator or the Galaxy Tab S10 FE+ (checklist in `docs/android-debugging.md`).
6. Merge, with a `CHANGELOG.md` `[Unreleased]` entry.
7. Release: bump version and lockfile, write `docs/release-notes/vX.Y.Z.md`, commit and push `main`, tag and push the tag, run `scripts/release.sh vX.Y.Z`.
8. Close issues only after device verification.
