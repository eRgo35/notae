## Notae v0.2.0

Notae keeps a personal sheet-music library organized: index PDFs on a Linux desktop with `notae-index`, then browse and search them on an Android tablet. This release works through the twenty tablet-feedback issues (#1–#20) and repairs the CI pipeline (#21).

**Please test on your own device.** Everything below was verified with host tests and on a disposable Android API 35 x86_64 tablet emulator. None of it has been accepted on the Galaxy Tab S10 FE+; see "Known limitations" and report findings as new issues.

### Correctness
- **#1 Startup:** the app no longer flashes an intermediate screen before All scores; it shows the library only once the startup state is known.
- **#13 Polish input:** Polish letters (ą ć ę ł ń ó ś ź ż) type into the Search field and are found by full-text search (host-tested through Slint input and FTS).
- **#18 Status:** a scan now reports the phase it is really in (Scanning library, Indexing N PDFs, Reading PDF text and thumbnails N of M, Checking for a desktop sidecar) and reports completion only after the sidecar check has finished. "Text pending" wording now says what to do next (run desktop OCR or import a sidecar) instead of implying OCR is running.

### Browsing
- **#14 Grid and list:** a header button switches the library between the card grid and a dense list; the choice persists.
- **#15 Score preview:** tapping a score opens a full-width preview with previous/next browsing instead of the left-panel details.
- **#16 Recent:** a tap on a score in Recent opens the PDF directly.
- **#17 Editing:** every card and row has an Edit icon, and a long press opens an actions menu (Open score, Score details, Edit details).
- **#20 Sidebar:** the sidebar can be collapsed; the choice is remembered separately for portrait and landscape (portrait starts collapsed).
- **#19 Scrollbars:** one themed, draggable, auto-hiding scrollbar on Library, preview, Search, Settings and Welcome.

### Search
- **#2** The search field is focused once after the transition settles, so the first tap should no longer show a stray cursor handle.
- **#3** Scope chips no longer shift when pressed.
- **#4** The "Press Ctrl K" sentence is replaced by a Ctrl K hint inside the search field (shown only when a hardware keyboard is present).
- **#5** The Scan button is gone from Search; a microphone action appears when Android provides a speech recognizer.

### Settings, Welcome, presentation
- **#8 / #9 / #11 / #12** Compact Welcome spacing; Settings redesigned (library folder, Library maintenance with indexed count and last scan, a more informative About, no pending-text paragraph, no privacy card); no Scan icon in the Settings header.
- **#7** Higher-contrast launcher icon, with rounded legacy masks.
- **#10** Short transitions between views, sheets and options (120/220 ms); disabled when Android animations are off.
- **#6** README gains a presentation layer with Library, Search and score-preview screenshots (labelled as emulator captures).

### Build and CI
- **#21** CI restored (host quality gates and Android arm64 compile), a release workflow that builds and signs the APK from version tags, a weekly dependency-advisory audit, and Dependabot configuration. See `docs/android-release.md`.

### Known limitations / not yet verified on the Galaxy Tab S10 FE+
- First-tap caret behaviour (#2), chip press/drag (#3), the keyboard-cover hint (#4), the voice recognizer (#5), the launcher icon on the device (#7) and motion in light and dark themes (#10) have only emulator and host evidence.
- Polish input with the Samsung Keyboard and Gboard (#13) is not yet verified; only the Slint input path and search are tested.
- Library, preview, scrollbar and sidebar behaviour on the tablet (#14–#16, #19, #20) is not yet accepted on the device.
- **TalkBack support for the item actions and menus (#17) is not available.** Slint's Android backend publishes no accessibility tree, so labels and actions that host tests check are not exposed to TalkBack; `uiautomator dump` with the long-press menu open shows only generic, unlabelled views.
- All screenshots are emulator captures of a non-sensitive fixture, labelled as such.
- Preview thumbnails are 400 px wide, so the full-width preview can look soft on a large tablet.
- The metadata and import modal sheets still use the standard scrollbar.
- The signed arm64 APK is verified (version, signature, SHA-256) but has not been launched on an arm64 device by the release process: the only emulator available is x86_64, where ARM translation aborts this build and the previous arm64 build identically (a `jni` ExceptionCheck panic). An x86_64 release-profile build of the same commit installed and launched on that emulator.
- Settings shows the Notae version and build identifier; the sidecar schema version is 2.

### Install
The signed arm64 APK (`notae-0.2.0-arm64.apk`) and its `.sha256` are attached to this release when published by the Release workflow. It is signed with the dedicated Notae release key, not the debug key: an existing debug-key install must be uninstalled first, which deletes the app's private data (index, preferences, folder grant). The PDFs are untouched and the index is rebuilt by scanning again.
