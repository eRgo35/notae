## Notae v0.2.1

Notae keeps a personal sheet-music library organized: index PDFs on a Linux desktop with `notae-index`, then browse and search them on an Android tablet. This is a follow-up to v0.2.0 that addresses the first round of tablet feedback (#10, #26, #27, #29, #30, #31, #33) and adds the contributor-facing documentation.

**Please test on your own device.** Everything below was verified with host tests and on a disposable Android API 35 x86_64 tablet emulator. None of it has been accepted on the Galaxy Tab S10 FE+; see "Known limitations" and report findings on the issues.

### Browsing
- **#26 Open on tap, Info icon:** tapping a card or a row opens the PDF in your viewer in every section (All, Recent, composers) and in both layouts. The pencil icon is replaced by an **Info** icon that opens the full-width score preview. Metadata is edited from the preview's **Edit details**; the long-press menu offers **Open score** and **Score details**.
- **#27 Needs details:** the "Needs details" section is gone from the sidebar, the chips, the counts and the empty states. Filename-derived ID and title and **Edit details** are unchanged.
- **#33 Text pending (interim):** the "Text pending" section and the "No text yet" badge are gone. PDFs without an extractable text layer stay in the library and are searchable by title and metadata. Settings → Library maintenance shows **PDFs without extractable text** as a plain count. This is interim behaviour until the OCR question (#28) is decided.

### Settings and scanning
- **#29 Settings:** the Scan button in Library maintenance is removed (Scan lives in the Library header only) and the maintenance card has the same density as the Library folder and About cards.
- **#30 Scan progress:** the bar no longer starts with a pre-filled stretch. Until "Reading PDF text and thumbnails: N of M" has a real total it is an empty track with a moving segment; the filled portion is exactly N of M.

### Motion
- **#31 Sidebar and #10 view changes:** the sidebar slides and fades when it is expanded or collapsed, and changing between Welcome, Library, Search, Settings and the preview is a fade-through with a short slide. The leaving view stays visible while it fades out and cannot be tapped. Motion is disabled when Android animations are off. On the emulator the transitions were checked frame by frame; on the tablet they have not been seen yet (see below).

### Documentation and project files
- README with screenshots refreshed from this build, `CONTRIBUTING.md`, `SECURITY.md`, issue and pull request templates (#6), a `CHANGELOG.md`, and an on-device OCR proposal (ADR `docs/adr/0001-on-device-ocr.md` and design, #28).

### Known limitations / not yet verified on the Galaxy Tab S10 FE+
- **Motion on the tablet is unconfirmed (#10, #31).** The emulator shows the transitions, but the cause of "no visible animation" on the tablet is not known. The app logs `notae: motion animator_duration_scale=... animations_enabled=...` at startup; if the scale is 0 or animations are off in Android's developer options, the app deliberately jumps instantly. Frame-level evidence from the tablet (a screen recording) is still outstanding.
- **Settings density (#29):** the "enormous" maintenance card could not be reproduced on the emulator at wide or compact sizes in light or dark theme. The only excess height found, the 48 px Scan icon inflating the heading row, is removed. Please confirm on the tablet.
- **Open on tap (#26):** tap-to-open and Back restoring the position in a long library are verified on the emulator only.
- **On-device OCR (#28) is a proposal only.** Nothing runs OCR on Android; image-only PDFs rely on desktop OCR and the sidecar, as before.
- **Nutki is not included.** The maintainer's private library is not part of this release or this repository.
- All screenshots are emulator captures of a non-sensitive fixture, labelled as such.
- The inherited limitations of v0.2.0 that this release does not touch remain: Polish input with Samsung Keyboard/Gboard (#13) and the voice recognizer (#5) are unverified on the tablet, and the signed arm64 APK has not been launched on an arm64 device by the release process (the available emulator is x86_64).

### Install
The signed arm64 APK (`notae-0.2.1-arm64.apk`) and its `.sha256` are attached to this release when published by the Release workflow. It is signed with the same dedicated Notae release key as v0.2.0, so it installs over v0.2.0 and keeps your index, preferences and folder grant. An install made from a debug build must be uninstalled first, which deletes the app's private data; the PDFs are untouched and the index is rebuilt by scanning again.
